# KAI — ميثاق فريق التطوير

## الغرض

إكمال KAI كـ Governed Agent Runtime قابل للتشغيل التجريبي ثم الإنتاج، مع الحفاظ على مبدأ: النموذج يقترح، والسياسة والإنسان يقرران، والبوابة تنفذ، والدليل يثبت.

## الفريق

| الدور | المسؤولية | لا يملك قراراً منفرداً في |
|---|---|---|
| مالك المعمارية/Runtime | حدود Core، IR، دورة التنفيذ، قرارات ADR | تجاوز السياسة أو حذف الدليل |
| الأمن والهوية | الأسرار، OAuth، العزل، التهديدات، إدارة المفاتيح | تعطيل اختبارات الأمان |
| Backend/Data/Integrations | FastAPI، SQLAlchemy، Alembic، Google adapters | أثر خارجي بلا idempotency |
| QA/CI/Release | بوابات الجودة، الاختبارات، الحزم، release evidence | إعلان نجاح بوابة غير مشغّلة |

## قواعد العمل

1. كل تغيير صغير ومراجعته مرتبطة بنتيجة أو invariant.
2. لا تطوير فوق working tree غير معروف؛ يُحفظ baseline ويُوسم مصدر التغيير.
3. لا أسرار في Git أو artifacts أو سجلات CI.
4. لا أثر خارجي في اختبار unit؛ provider stub أو sandbox فقط.
5. كل ترحيل قابل للتطبيق في قاعدة فارغة وقابل للتحقق في بيئة معزولة.
6. أي عائق بيئي يُسجّل كـ blocked، لا يُستبدل بتخمين.

## بوابة الدمج

`git diff --check` → `ruff check .` → `mypy` → الاختبارات العادية → اختبارات الترحيل المعزولة → مراجعة أمنية → تحديث الوثائق.
